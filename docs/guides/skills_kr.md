## 상세 활용법 (Deep Dives)

### `/office-hours` (Y-Combinator 조언 모드)
단순 코딩 지침을 내리기 전에 **"당신이 만들고자 하는 제품을 진짜 사용자가 원하는가?"**를 철저하게 검증합니다.
- **예시 시나리오:** "달력을 요약해주는 브리핑 앱을 만들겠다"고 하면, "이건 단순 달력 요약이 아닙니다. 여러 구글 계정에 흩어진 일정과 자료를 정리해주는 '개인 비서 AI'에 가깝습니다"라며 진짜 사용자가 겪는 통증에 기반해 기획의 방향을 재정립(Reframe)합니다. 코딩 시작 전에 YC 파트너의 관점으로 사업성을 타격해줍니다.

### `/plan-ceo-review` (CEO 마인드 리뷰)
제품 기획안을 평가할 때, 평범한 결과물 대신 "별점 10점짜리 경험(10-Star Product)"을 만들어내도록 강력히 유도합니다.
- **예시 시나리오:** "중고 거래 시 판매자가 사진을 업로드하게 해달라"고 지시하면, "단순히 사진만 올리는 게 아니라, AI가 사진을 판독해 상품명, 스펙, 적정 가격대를 자동으로 채워주는 프리미엄 등록 시스템을 만들자"고 제안하여 단순 기능 구현을 뛰어넘는 비즈니스 가치로 이끕니다.

### `/plan-eng-review` (설계 및 아키텍처)
기획이 통과되면, 코드를 작성하기 전에 시스템 아키텍처, 데이터 흐름, 에러 처리, 예외 케이스를 먼저 꼼꼼하게 검토합니다.
- **예시 시나리오:** "만약 외부 API가 멈춘다면?", "비동기 큐 작업 도중 에러가 나면 어떻게 롤백할 것인가?" 같은 예외 질문을 던지며, 계획의 빈틈을 찾기 위해 Sequence, State, Component 다이어그램 등을 ASCII 코드로 그리도록 하여 아키텍처의 빈틈을 시각적으로 정렬합니다.

### `/review` (시니어 코드 리뷰)
테스트를 통과한 코드라도 완벽하다고 믿지 않습니다. `/review`는 스레드 경쟁 상태(Race Condition), 데이터베이스 N+1 조회 병목, 유실된 인덱스, 부족한 예외 처리 등 프로덕션 환경의 실전 에러를 미리 발견합니다.
- **결과물:** 기계적이고 자명한 버그들은 즉시 `[AUTO-FIXED]` 태그와 함께 자동 수정하며, 근본적인 구조 결함에 대해서는 사용자에게 정중히 질문하여 피드백을 요구합니다.

### `/investigate` (체계적인 디버깅)
**철칙:** "원인 분석 없이 짐작만으로 코드를 땜질하듯 고치는 행위를 엄격히 금지합니다."
- 에러를 만나면 즉시 코드를 수정하지 않고, 에러 로그와 파일 구조를 탐색하여 최소 3가지 가설을 세웁니다. 가설을 `console.log`나 디버거로 확실하게 검증하여 입증된 경우에만 코드를 수정합니다.

### `/qa` (자동화 QA)
코드가 작성되면 사용자가 지정한 도메인이나 로컬 URL을 바탕으로 AI가 백그라운드 브라우저를 띄워 실제 마우스 클릭, 폼 입력, 흐름 테스트 등을 진행합니다.
- 브라우저 콘솔 에러, UI 깨짐 등을 스크린샷과 함께 포착하고 해당 파일의 버그를 찾아내어 수정 및 검증을 완료하고 커밋까지 수행합니다.

### 커스텀 특화 스킬 상세 소개

### `/developer-guidelines` (카파시 가이드라인)
AI 코딩 시 흔히 저지르는 **"무의미하게 길어지고 복잡해지는 코드(LLM Slop)"**를 방어하기 위한 개발 규칙입니다.
- 불필요한 추상화나 과도한 구조화를 쳐내고, 수정을 요구받은 코드에 대해 가장 단순하고 수정을 최소화하는 "가장 짧고 명확한 패치"만을 유도하여 유지보수가 불가능해지는 현상을 막습니다.

### `/biz-ops-guideline` (마케팅 & 고객 지원)
개발된 제품을 시장에 알리고 고객 문의에 대응하는 비즈니스 운영 단계로 전환합니다.
- **마케팅 (Marketing):** 타겟 고객들의 클릭을 유도하는 CTA(행동 유도) 카피와 기술 블로그 글, SNS 홍보 문구를 작성합니다.
- **고객지원 (CS):** 에러나 장애 발생 시 변명 대신 [공감 ➡️ 원인 규명 ➡️ 대안/보상 제시]의 3단계 템플릿에 따라 고객 신뢰를 회복하는 CS 이메일/메시지를 빠르게 작성합니다.

### `/monetization-strategy` (수익화 아키텍처)
제품의 결제 및 유료 회원 전환 흐름을 결합시키는 스킬입니다.
- **가격 정책 (Pricing):** 3단계 요금제 구성을 기본으로 하여 사용자의 Pro 등급 결제를 유도하는 미끼 상품(Decoy) 배치 및 가치를 패키징합니다.
- **결제 연동:** 외부 PG사(PortOne) 및 Stripe의 결제 완료 웹훅(Webhook) 흐름과 예외 처리를 검토하여 결제 단계에서의 이탈(Drop-off)을 최소화하도록 연동합니다.

### `/cicd-devops-guidelines` (DevOps 가이드)
- 소규모 및 1인 개발 환경에서 배포와 인프라의 안정성을 극대화하기 위해, 테스트 자동화, API Mocking, 완벽하게 패키징된 `Dockerfile` 관리 등을 조율하는 스킬입니다.
