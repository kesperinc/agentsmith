# Agent Smith IDE 개발 환경 구축 및 인수인계 문서 (Handover Document)

본 문서는 다른 컴퓨터에서 **Agent Smith IDE (Custom Code-OSS AI Editor)**의 개발 및 빌드 환경을 동일하게 100% 재현하고, 발생 가능한 예외 사항(컴파일 오류 등)을 해결하기 위한 상세 인수인계 가이드라인입니다.

* **최종 작성일**: 2026년 8월 12일
* **대상 프로젝트**: `Agent Smith IDE`
* **개발 기조**: Windows 환경 선구축 (Phase 1) 및 Linux/Red Hat 이식 (Phase 2)

---

## 1. 개발 장비 기본 요구사항 (Prerequisites)

타 장비에서 개발을 시작하기 전, 아래의 인프라 도구가 미리 준비되어 있어야 합니다.

1. **Node.js LTS**: v18.17.1 (프로젝트 내에 내장된 포터블 Node.js 경로를 자동 사용하도록 세팅되어 있습니다.)
2. **Yarn**: 글로벌 설치 권장 (`npm install -g yarn`)
3. **Python**: v3.10 ~ v3.14 (가상환경 `.venv` 가 프로젝트 루트에 구축되어 있어야 합니다.)
4. **Git**: 최신 윈도우용 Git 설치
5. **Visual Studio Build Tools 2022**: C++ 컴파일러 및 MSBuild 환경 구축 필수

## 2. 핵심 트러블슈팅: MSBuild Spectre 완화 오류 (MSB8040) 해결 

Yarn 의존성 설치(`yarn install`) 도중 `@vscode/spdlog` 또는 `@vscode/policy-watcher` 등의 Native C++ 모듈 빌드가 `MSB8040` 오류로 중단되는 경우, 아래 조치를 취해야 합니다.

### 🛠️ Spectre 완화 라이브러리 직접 설치 방법 (필수)
1. **Visual Studio Installer** 실행 ➔ **수정(Modify)** 클릭.
2. **개별 구성 요소(Individual Components)** 탭으로 이동.
3. 검색창에 `spectre` 입력 후 아래 항목을 체크하여 설치합니다:
   - **`MSVC v143 - VS 2022 C++ x64/x86 Spectre 완화 라이브러리(최신)`**
4. 설치 완료 후 터미널을 재기동하고 빌드를 다시 수행합니다.

### 💡 보완용 MSBuild 설정 파일 우회 방법
프로젝트 루트 또는 `vscode/` 디렉터리 내에 [`Directory.Build.props`](file:///c:/dev/antigravity-workspace/aifullstack/agentsmith/vscode/Directory.Build.props) 파일을 아래 내용으로 두면 MSBuild가 스펙터 완화 기능을 우회하여 빌드를 지원합니다:
```xml
<Project>
  <PropertyGroup>
    <SpectreMitigation>false</SpectreMitigation>
  </PropertyGroup>
</Project>
```

## 3. 개발 셋업 및 빌드 실행 순서 (Windows)

새 컴퓨터에서 빌드 환경을 다시 셋업하는 1-Click 실행 프로세스입니다.

### 1단계: Upstream Clone 및 의존성 복구
프로젝트 루트에서 [`build_agent_smith.bat`](file:///c:/dev/antigravity-workspace/aifullstack/agentsmith/build/build_agent_smith.bat) 배치 파일을 실행합니다.
```cmd
cd c:\dev\antigravity-workspace\aifullstack\agentsmith\build
.\build_agent_smith.bat
```
- **수행 내용**: `vscode/` 디렉터리가 비어 있거나 없을 경우 자동으로 `microsoft/vscode` (Tag `1.86.0`) 소스코드를 클론하고 컴파일 모듈을 매핑합니다. 
- *주의*: 빌드 스크립트 내부에는 `SpectreMitigation=false` 환경변수와 내장 포터블 node `PATH` 선언이 포함되어 있습니다.

### 2단계: 배포 버전 번호 주입 자동화
배포 릴리즈 버전을 주입해야 할 경우 [`inject_version.bat`](file:///c:/dev/antigravity-workspace/aifullstack/agentsmith/build/inject_version.bat)를 호출합니다.
```cmd
cd c:\dev\antigravity-workspace\aifullstack\agentsmith\build
.\inject_version.bat
```
- **결과**: `package.json` 및 `product.json` 버전에 한국 표준시(KST) 타임스탬프가 적용된 고유 식별자(`1.86.0-YYYYMMDD.HHMMSS`)가 주입됩니다.

## 4. Git 형상 관리 및 브랜치 가드레일 전략

새 장비에서도 아래 정의된 Git 브랜치 전략을 100% 충족하여 작업 및 커밋을 진행해야 합니다.

- **원격 저장소 주소**: `https://github.com/kesperinc/agentsmith.git`
- **브랜치 가드레일**: 
  - `main`: 상용/최종 릴리즈 브랜치
  - `staging`: 통합 테스트 및 사전 배포 대기 브랜치
  - `feature/*` (예: `feature/setup-git-guardrails`): 단위 작업용 피처 브랜치

### 권장 커밋 및 동기화 워크플로우:
1. `feature/*` 브랜치 생성 후 변경 사항 작업 및 로컬 커밋
2. `feature/*` 원격 푸시 ➔ `staging` 브랜치 체크아웃 ➔ 피처 병합(merge) ➔ `staging` 원격 푸시
3. `main` 브랜치 체크아웃 ➔ `staging` 병합 ➔ `main` 원격 푸시
4. 작업 완료 후 다시 본인의 `feature/*` 브랜치로 복귀하여 대기
